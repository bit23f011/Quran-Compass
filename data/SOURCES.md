# Quran data and attribution

## Surah catalogue

`surahs.js` provides 114 chapter records with the Arabic name, a conventional English transliteration and name translation, ayah count, Meccan/Medinan classification, conventional revelation order, and the range of juz covered by the chapter. Every record also includes a short editorial overview and three or four key themes describing the chapter's content. It is generated by `build_data.py`.

The catalogue uses the common Hafs/Kufan ayah numbering: 114 chapters and 6,236 numbered ayahs. The 30 juz boundaries are encoded explicitly. Revelation order and the classification of some chapters vary between scholarly traditions; these fields describe a conventional catalogue and should not be presented as undisputed historical dates.

Reference resources for checking the catalogue:

- Tanzil Quran metadata: https://tanzil.net/docs/quran_metadata
- Quran.com chapter catalogue: https://quran.com/
- Risan Quran JSON project: https://github.com/risan/quran-json

The current catalogue was compiled locally and checked for structural consistency. It has not yet been compared byte for byte with a downloaded source in this environment.

The overviews and theme labels are concise reading aids written for navigation. They are not Quranic text, a verse translation, a comprehensive tafsir, or a statement of special spiritual benefits. They avoid specific revelation-occasion claims and unsupported reports about virtues. Consult the actual chapter and a qualified commentary for interpretation.

## Complete verse text and translations

The intended public source is Risan's `quran-json` distribution, which includes Arabic text and language editions. Source repository: https://github.com/risan/quran-json. NPM package: https://www.npmjs.com/package/quran-json.

The standard distribution endpoints are:

- Arabic: https://cdn.jsdelivr.net/npm/quran-json@3.1.2/dist/quran.json
- English: https://cdn.jsdelivr.net/npm/quran-json@3.1.2/dist/quran_en.json
- Urdu: https://cdn.jsdelivr.net/npm/quran-json@3.1.2/dist/quran_ur.json

These are candidate import endpoints, not evidence that the files have been downloaded or verified. Downloading external public data was blocked by a network sandbox, and the automatic approval review failed even after the user authorized the download. At the time of this note, complete Quran verse text and translations have not been bundled. `quran.js` contains an empty optional pack (`globalThis.QURAN = {}`), allowing the offline catalogue to work while installation is pending. The application must not claim that the complete text is available until `quran.js` is populated and validated.

Before distributing a populated verse bundle, retain the upstream attribution and content-license information, confirm the actual translation editions from their source metadata, and validate all 114 chapters and all 6,236 numbered Arabic ayahs. Preserve Arabic text verbatim. Translation text is a rendering of the meanings, and is not the Quranic Arabic itself.

## Detailed study references

`study.js`, generated by `build_study.py`, contains a short introduction copied from each existing chapter overview, a general reading guide, reflection questions based on that chapter's existing themes, and links to its Quran.com chapter and English Tafsir Ibn Kathir page. These are editorial navigation aids, not quotations or new authoritative interpretations. They do not fabricate revelation occasions, spiritual benefits, hadith, or word-by-word translations.

The chapter and tafsir URL formats are configured references. Their pages were not fetched in the authoring environment, so they must not be presented as a downloaded, verified offline tafsir pack. Online connectivity is required to open them. No complete tafsir, shan-e-nuzool collection, or word-by-word linguistic corpus has been bundled.

## Installing previously downloaded source files

If an allowed connection can save the official distribution's `quran_en.json` and `quran_ur.json`, install both locally without network:

```sh
node scripts/download-quran.mjs --english quran_en.json --urdu quran_ur.json --en-source "Sahih International" --ur-source "Fateh Muhammad Jalandhry"
```

The local-file path verifies all 114 chapters, 6,236 numbered ayahs, sequential verse IDs, non-empty translations, and byte-identical Arabic text across the editions. It records SHA-256 hashes of the supplied files. Those structural checks do not independently authenticate the supplied Arabic, translation authors, or content licenses; edition names must match the files actually supplied. Without explicit labels, local imports display an unspecified edition rather than assuming an author or language from generic translation fields.

The network installer verifies the official npm package's SHA-512 integrity before parsing any content and retains upstream package README/license metadata when available. It never executes upstream code. Both paths create the same validated `surah-compass-quran-v1` combined pack for offline reading and browser import.

The subsequent user-approved download attempt was also blocked: default fetch failed and the elevated command failed automatic review with internal `content-blocked` (request `202611080123466170031342rskr6lTvFhzp`). It was not executed and was not a determination that the source is unsafe. Full Quran text remains unbundled unless the installer succeeds later.

## Multilingual editions, reciters, commentary, and spoken translations

`editions.js` contains configured public-source references for 25 reciters on EveryAyah, 20 text-translation editions on AlQuran.Cloud (including six English and three Urdu editions), four tafsir references (Arabic Al-Muyassar/Al-Jalalayn and English Ibn Kathir/Ma’ariful Quran), and the `en.walk` / `ur.khan` spoken-translation candidates. These entries are marked `configured`: they are source references, not claims that each endpoint was successfully checked or that audio files are bundled. Runtime discovery reads actual provider metadata and marks confirmed entries `verified`. EveryAyah catalog verification confirms metadata; each audio file is still checked when played or downloaded.

The runtime content sources are:

- AlQuran.Cloud API catalog: `https://api.alquran.cloud/v1/edition`
- AlQuran.Cloud chapter edition: `https://api.alquran.cloud/v1/surah/{surah}/{edition}`
- Quran.com public tafsir resources: `https://api.quran.com/api/v4/resources/tafsirs`
- Quran.com chapter tafsir: `https://api.quran.com/api/v4/quran/tafsirs/{resource}?chapter_number={surah}`
- EveryAyah reciter metadata: `https://everyayah.com/data/recitations.json`
- EveryAyah recitation files: `https://everyayah.com/data/{subfolder}/{surah-and-ayah}.mp3`

No API credentials or user information are sent to these content sources. `content.js` only fetches editions on explicit discovery/load actions; startup reads existing local storage. Source responses must match the requested edition, language, format, chapter, and canonical numbered ayahs before their content is accepted. Arabic is preserved byte for byte. Text translations retain their source edition/author attribution; a translation renders meanings and is not the Arabic Quran.

Commentary is converted from source markup to plain text for display. Source-grouped ayah references and coverage gaps are retained: a commentary that covers a passage is not invented or duplicated into separate authoritative interpretations. Quran.com resource metadata is verified before accepting a configured commentary. No tafsir, narration occasion, hadith, word-by-word linguistic corpus, or translation has been generated to fill missing source content.

Spoken translations must be reported by their source as `format=audio` and `type=translation` in a non-Arabic language. Arabic recitation is never labelled as translated speech. Per-ayah speech URLs are accepted only on the vetted HTTPS Islamic.Network audio hosts and must contain the requested edition identifier. Stored speech metadata contains URLs; it does not mean the corresponding audio files have been saved offline. The reader separately caches the actual audio files. No TTS, voice cloning, or speech synthesis is used.

Accepted chapter editions are saved in the dedicated `compass-editions-v1` IndexedDB database for offline reuse. A successful in-memory load whose persistence fails is explicitly reported as `persisted=false`; the UI must not claim that it was downloaded for future offline sessions. Removing a cached edition removes its local text/metadata record. Publisher/content terms still apply; provider attribution is preserved, and no independent content-license audit or blanket redistribution permission is implied.

Live metadata verification in the authoring environment remains unavailable: default reads of the three metadata sources failed `EACCES`, and a new user-authorized elevation failed automatic review with internal `content-blocked` (request `202611081734026975292245rwkna2lzxzGZ`). The elevated action was not executed. Tests use clearly labelled fixtures and mocked fetch/IndexedDB; they verify validation, caching, cancellation, and source-type handling, not live source availability.
